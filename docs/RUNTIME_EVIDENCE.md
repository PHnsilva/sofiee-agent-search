# Evidência do runtime local — issue #7

O runtime valida chamadas estruturadas do contrato v1 e produz um plano imutável para um provedor explicitamente configurado. Preserva pedido, consulta, cada filtro (incluindo categoria e cor), dicas de fonte, ordenação, limite da página e cursor. Dicas de origem são apenas contexto e nunca viram uma whitelist global.

O adaptador do provedor é uma interface, não uma fonte implementada. Sem provedor, a chamada retorna `source_unavailable`, sem resultados sintéticos e sem remover ou enfraquecer filtro/ordenação. Quando um provedor é injetado, o núcleo valida o contrato da resposta, exige auditoria de cada filtro na ordem recebida, verifica a coerência de filtros obrigatórios e exige que a ordenação solicitada seja reportada. Falha estrutural retorna `filter_unrepresentable` sem expor os resultados não validados.

Os testes de provedor usam apenas o fixture sintético do contrato para verificar a interface; não são busca real nem evidência de acesso a Mercado Livre, SHEIN ou qualquer outra fonte. Nenhum cliente HTTP ou fonte foi habilitado. O adaptador Ollama local está disponível de modo opt-in, mas não é necessário quando consulta e filtros já são estruturados; não houve chamada de modelo ou alegação de qualidade semântica. Sem provedor conectado, não há resultado útil de busca disponível ao consumidor.

O limite de entrada do CLI é 80.000 bytes, o contrato limita cada consulta e paginação a 100 resultados, timeout do provedor é configurável entre 1 e 120 s, e uma chamada de fonte por processo é permitida de cada vez. O evento de cancelamento é encaminhado ao provedor e uma saída recebida após cancelamento é descartada. Não há limite rígido de memória para um provedor externo; cada provedor futuro precisa honrar o timeout e o cancelamento cooperativo. `scripts/measure_runtime.py` mede 1.000 compilações do plano local em memória; duas execuções no host mediram 9,23 ms e 10,88 ms, sem CLI, rede, modelo ou pesquisa de fonte.

Validação no CPython 3.13.15: `python -m unittest discover -s tests -v`, `scripts/validate_contracts.py`, `scripts/check_environment.py`, `scripts/measure_runtime.py` e `git diff --check`. Os casos verificam filtros de camisa branca (categoria, cor, tamanho e frete), preservação de ordenação, ausência de provedor, filtro omitido, resultado contraditório, timeout e cancelamento. As fixtures validam a fronteira; não demonstram recuperação ou ordenação de dados reais.
